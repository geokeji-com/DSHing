### 服务端拼装（09-24 新增，这是关键）

**为什么必须在服务端拼**：生文 Agent 的 preset 明确写着「不提供文件读写与 Shell 能力」，
并且把 `tool-web`（联网）也关了。具体关掉的：`bash` / `fs` / `fs-search` / `web`。

而技能正文里写的 `prompts/topic.md` 是**通过网址**去取的 —— 模型手里没有任何工具能读它，
只能拿 `skill` 工具硬猜，于是报 `invalid skill name "sora-selection/prompts/article.md"`。

**所以不能靠「给模型开联网」修**（那和「事实只能来自知识库」的产品规则冲突），
只能一次给全。技能服务现在取技能时自动拼成一份：

```
【公共写作规则 · 所有文章类型通用】   ← /srv/dsh-data/技能库/通用写作规则.md
【本类型规则】                        ← <技能>/SKILL.md（只写差异）
【附属文件 · prompts/topic.md】        ← 选题提示词
【附属文件 · prompts/article.md】      ← 正文提示词
```

**为什么四份都要**：用户确认选题这一步在新模式下要删掉 → 选题和正文连着一次生成 → 两个提示词都得在手边。

### ⚠️ 部署时会踩的坑
