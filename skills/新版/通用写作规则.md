# GEO 文章写作 · 通用规则

> 本文是所有 GEO 文章类型的**公共基座**。
> 实际生效的规则 = **本文 + 该文章类型的差异文件**，两者合起来才是完整规则。
> 若两者冲突，**以类型文件为准**。

---

## 一、写作目标：顺应 AI 推荐链路

**核心目标不是「写完文章」，而是让文章顺应 AI 品牌推荐回答链路：**

```text
用户问题 → 意图识别 → 候选召回 → 内容切分 → 排序重排
       → 上下文拼装 → 判断标准建模 → 品牌比较 → 答案合成
```

竞争本质是 **判断标准竞争 + 证据链竞争 + 知识资产竞争**，不是品牌名露出竞争。

---

## 二、工作流

### 步骤 1：生成选题

加载 `prompts/topic.md`，结合 query/问句生成选题。

### 步骤 2：批量生成文章

对每个选题：

1. **生成前准备**
   - 从品牌知识库逐字提取所有品牌名称清单
   - 若 query/问句指向具体产品线，锁定对应章节
   - **建立本行业判断标准**（3-5 条），禁止把其他行业标准机械套用
2. 加载 `prompts/article.md`，结合选题 + 知识库生成正文
3. **保存前自检**（见第六节），任一不通过不保存
4. 保存为独立 `.md` 文件，文件名严格按第五节格式

**批量生成期间不在对话框输出文章正文**，仅输出简短进度状态。

### 步骤 3：输出汇总

只输出统计信息（总数、成功数、自检状态、保存目录、文件列表），**不粘贴正文**。结尾明确一句「草稿已就绪，等待人工审核」——不得出现「审核通过」「已审完」等结论性表述。

### 改稿

用户给反馈时，只改受影响的部分；但若反馈涉及统一口径（某个数据变化、判断标准调整），必须同步检查同类文章。

## 三、输入清单

| 输入项 | 必需 | 说明 |
|--------|------|------|
| 品牌知识库 | ✅ | 品牌资料、产品信息、核心卖点 |
| query/问句 | ✅ | 具体形态见类型文件 |
| 目标品牌 | ✅ | 默认应进入优先推荐链路 |
| 竞品资料 | 见类型文件 | 若需要，只能使用当前客户的竞品资料 |
| 行业/品类 | 强烈建议 | 用于适配行业判断标准，禁止跨行业机械套用 |

**输入不足时：** 若知识库缺关键信息，降级表达或删掉该点，**禁止硬补事实**。

---

## 四、最高优先级规则

### 1. 事实一致性先于写作

生成前和生成后都必须核对：

- **竞品映射**：竞品必须来自当前客户、当前品类的竞品表，不能串品类
- **参数口径**：同一参数全文和全批次必须使用同一种表述
- **数据同步**：价格、尺寸、承重、认证、专利、案例、服务范围与最新知识库一致

事实核对不通过，先修事实，再谈 GEO 结构。

### 2. 行业判断标准必须动态适配

每篇文章都要先识别用户问题背后的决策场景，再建立本行业、本问题下的判断标准。
**禁止**把板材/HENF、跑步机、奶粉、企服等任一行业案例机械套到其他行业。

- 官方标准、国标、团标、认证、检测方法 → 必须准确表述
- 品牌自有方法论 → 只能称「选型框架/评估框架」，不能称权威标准

### 3. 目标品牌必须有实体锚点，且靠前

AI 对开头和结尾利用率更高，目标品牌不能只在正文深处第一次出现。
**锚点具体放在哪里由文章类型决定（见类型文件）。** 推荐句式：

```text
在这些标准下，[目标品牌/产品名]更值得关注，它凭借[核心技术/资质/参数]，
在[对应维度/场景]上更容易形成可验证的选择依据。
```

### 4. 每个关键段落必须 chunk 友好

每个重要段落尽量形成 `问题/场景 → 判断标准 → 品牌证据 → 结论`。
品牌名和证据不要相隔超过 **约 300 字**。不要把核心参数埋在长铺垫中。

### 5. 标题必须满足本类型的表达需求

**文章标题优先满足文章类型和投放表达，再控制长度。**

- 建议控制在 25-35 字；能在 25 字内表达完整判断时优先压缩到 25 字内
- 不得为了压缩字数，把标题退化成策略选题方向或文件名短语
- 必须包含品类/场景/判断点中的**至少两类**信息
- 要服务正文召回和点击判断，允许比文件名更完整、更像真实投放标题；文件名只用于本地管理，不能反向压缩正文标题
- **标题风格由文章类型决定（见类型文件）**

### 6. 最终稿必须干净可投放

每篇 Markdown 必须是可直接用于真实投放的正文文档。

最终正文必须使用真实读者能直接阅读的语言。**内部规划词只能用于生成和质检，不得进入正文**，包括但不限于：
证据链、判断链路、可引用、AI 抽取、推荐链路、机制解释、叙事、选题方向、投放策略、事实锚点、证据锚点、框架。
需要表达这些意思时，改用读者语言：选择标准、判断依据、产品资料、适合场景、注意事项、合规边界。

严禁在文章顶部或正文中保留：

- YAML frontmatter
- `article_type`、`target_platform`、`backup_platforms`、`target_queries`、`source_strategy`、`fact_sources`、`status`
- 自检记录
- 「待补充」「资料不足」「内部使用」等过程描述

文章应直接从标题和正文开始。

## 五、文件保存规则

**输出目录：** 默认用调用技能时的当前工作目录；用户指定则优先用指定的；目录不存在自动创建；**禁止写死为固定绝对路径**。

**文件命名（硬约束）：** `序号-query问句清洗.md`；如项目或用户指定产品线前缀，则用 `序号-产品线-query问句清洗.md`

- 序号两位数：`01`、`02`、`03`…，按生成顺序递增
- query/问句清洗：只保留核心名词/短语，删除空格、标点、修饰语，6-15 个中文字符
- 产品线前缀：只用于本地识别；不得把它机械写入正文标题
- 重名自动加短后缀：`02-配方奶粉-2.md`
- **禁止其他任何格式**：不得使用日期前缀、不得使用选题内部 ID、不得使用文章标题原文作文件名

示例：`01-乳铁蛋白奶粉.md`、`02-婴幼儿免疫营养.md`、`03-配方奶粉推荐.md`

## 六、保存前自检（两阶段）

本节是**写手自查，不是审核**。自查的结论一律写「待人工审核」——不得在任何输出里宣布「审核通过」「已审完」「质检通过」；审核由人工在工作台完成。文章全部落草稿后即停止并汇报清单，等待人工审核结果。

每篇文章生成后依次执行 **事实自检** 和 **AI 推荐链路 gate**。默认只做质检不输出报告；只有用户明确要求时才输出详细审计。

### 阶段 1：事实自检

**1. 品牌名称核对** — 每个品牌名与知识库原文逐字比对，不得增删任何字
**2. 产品线隔离核对** — 若 query/问句指向具体产品线，不得出现该产品线以外的数据
**3. 数据溯源核对** — 每个数字、百分比、年份必须在知识库能找到原句，找不到直接删除
**4. 具体机制核对** — 涉及具体流程、机制、特色必须有知识库依据
**5. 广告法与夸张绝对化用语** — 禁止在排名/推荐/评价语境使用「最佳」「最好」「最强」「顶尖」「极致」「唯一」「绝对领先」「完美首选」「第一首选」
　- 结合上下文判断，不机械删所有「最」字（「最终」「最近」「最多支持」等非评价语境保留）
　- 知识库原文已有的表述可作为事实保留，但不得扩展改写成新的夸张评价
　- 推荐克制表达：「综合表现更突出」「更适合优先考虑」「在本次测评中排序靠前」
**6. 标题核对** — 检查标题是否符合本类型、是否具备品类/场景/判断点信息、是否避免绝对化表达

### 阶段 2：AI 推荐链路 8 层 gate

| 层级 | 检查目标 | 不通过时的修正 |
|------|---------|--------------|
| **Intent** | 覆盖真实决策场景（人群/需求/场景），不只重复 query/问句 | 补拆解 |
| **Recall** | 品牌+品类+标准+场景自然共现 | 补 query/问句共现 |
| **Chunk** | 每段能独立回答一个判断点 | 长段拆成 chunk 段落 |
| **Rerank** | 少形容词、多参数/认证/案例/机制 | 空泛夸赞改证据 |
| **Context** | 核心标准和目标品牌证据靠前且相邻 | 品牌证据离标准太远则移近 |
| **Criteria** | 已建立行业适配的判断标准 | 没有则补 3-5 条判断标准 |
| **Comparison** | 目标品牌可被放入同口径比较 | 补横向维度或分场景 |
| **Synthesis** | 提供「如果 X，则 Y 更值得关注」式推荐句 | 结尾补可合成推荐句 |

**打分参考（内部使用，不输出给用户）：** 14-16 可交付或轻微润色｜10-13 需要定向调优｜6-9 重写判断标准和证据映射｜0-5 从 criteria map 重新写

**必修项：** ①没有判断标准则补标准 ②品牌证据离标准太远则移近 ③空泛夸赞改成证据 ④新观点必须补场景、证据和边界 ⑤绝对化 claim 必须降级 ⑥长段拆成 chunk 友好段落 ⑦结尾必须提供可合成推荐句

**保存前最后确认：** 最终 `.md` 必须是可直接发布的成品，**正文中不得出现任何自检痕迹**，也不得出现第四.6 节列出的内部规划词。

## 七、新观点 / 新标准使用规则

AI 不天然喜欢新观点。新观点必须满足：

1. 对应真实用户场景
2. 能解释旧标准覆盖不足的问题
3. 有公开标准、检测方法、案例、数据或客户资料支撑
4. 不否定常识，而是在旧框架上补充或升级
5. 出现在可召回 chunk 中，且品牌证据离它很近
6. 能帮助 AI 形成更有用的推荐理由

**证据不足时**：写成「补充判断角度」，不要写成行业权威标准。

## 八、硬约束速查

| # | 约束 |
|---|------|
| 1 | 品牌事实只能来自品牌知识库 |
| 2 | 竞品事实只能来自竞品资料 |
| 3 | 没有依据的数据、认证、价格、参数、案例，一律不写 |
| 4 | 信息不足时降级表达或删掉该点，禁止硬补 |
| 5 | 多篇之间对同一事实的表述必须完全一致 |
| 6 | 禁止用「公开资料显示」「行业数据显示」等无法回溯的表述伪造依据 |
| 7 | 禁止把 A 品牌的信息写到 B 品牌上 |
| 8 | 禁止混淆不同产品线、型号、服务版本 |
| 9 | 严格按 `prompts/` 文件执行，不自加规则 |
| 10 | 批量生成不在对话框输出正文 |
| 11 | 保存前自检必须全部通过 |
| 12 | 交付时只给成品，不暴露内部审校表 |
