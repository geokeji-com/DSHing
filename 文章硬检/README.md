# 文章硬检

生成的文章发出去之前，先让脚本扫一遍，挑出**一眼就知道不能发**的东西。

纯正则 + 结构检查，**不调模型、不花 token**，一篇几毫秒。跟客户、跟知识库**无关** ——
一套规则所有客户通用，不用一家配一遍。

## 它查什么

```sh
node 硬检.mjs --规则
```

三组，26 条：

| 组 | 查什么 |
|---|---|
| **工程痕迹** | 我们交代给 agent 的话漏进了正文：知识库、关键词布局、证据链、事实锚点、自检记录、`article_type` 字段、「以下是为您生成」、占位符没填 |
| **合规** | 广告法绝对化用语、排他性说法（要有出处）、医疗违禁词、贬损竞品 |
| **格式** | `**` 没闭合、代码块没闭合、表格列数不齐、标题跳级、字面量 `\n`、整段重复、序号断裂 |

## 三档结论

| 档 | 意思 | 挡入库？ |
|---|---|---|
| **拦** | 确定是硬伤 | 挡 |
| **证** | **可能是真的，但要有出处** | 挡 |
| **提** | 疑似，人看一眼 | 不挡 |

「证」这一档是专门为**真的是第一、真的是唯一一家**的品牌留的。

市场监管总局《广告绝对化用语执法指南》（2023）第六条(六)：限定了具体时间、地域条件，
宣传销量 / 市场占有率等**事实信息**的，不算违规；但第七条紧跟一句：**无法证明其真实性的，
照样查处**。脚本查不了「拿不拿得出证据」，所以不判对错，只提醒「这句要有出处」。

**同一句里带了限定口径（年份 / 地域 / 数据来源）的，自动降到「提」，不挡入库**：

```
该品牌销量第一                                          → 证（挡住，要出处）
据中国口腔医疗协会 2024 年度报告，该品牌在中国大陆地区销量第一   → 提（已带口径）
```

所以真的是第一的品牌，按合法写法写就不会被挡 —— 顺带引导把口径和来源补上。

## 它不查

- 文章写得好不好、逻辑通不通（语义活，正则做不了）
- 事实对不对（价格、地址、参数）—— 要等知识库改成分块存储才好做
- 字数、H2 几个、有没有 FAQ —— 按文章类型不同（仿写就没 FAQ 段），硬判就是误报。
  只当统计数字摆着，不给红灯

**保的是下限，不是质量。**

## 用

```sh
node 硬检.mjs 某篇文章.md              # 查一篇
node 硬检.mjs 某个目录/                 # 查目录下所有 *.md（不递归）
node 硬检.mjs --规则                   # 只看它查什么
node 硬检.mjs --json 某篇文章.md        # 出 JSON，给别的程序用
```

退出码：有「拦」或「证」→ `1`，否则 `0`（CI / 脚本能直接用）。

## 加词 / 改规则

改 `lib/规则表.js` 就行，**不用碰代码**。它是一张纯数据表：

```js
{
  id: 't1',
  group: '工程痕迹',
  name: '元指令语汇',
  level: 'fail',            // fail 拦 / proof 证 / warn 提
  why: '我们交代给 agent 的话漏进了正文',
  words: ['知识库', '数据口径', ...],   // 出现即命中
  res: [/关键词(严禁|不得|布局)/g],      // 要看搭配的用正则
  allow: [/最终/, /^最好(由|先)/],       // 豁免：^ 开头的只往命中位置后面看
  qualifier: true,          // 带限定口径就从 proof 降到 warn
}
```

改完把 `RULES_VERSION` 往上抬一位 —— 工作台那边的旧检查结论会自动作废。

**误报比漏报致命**：被烦两次以后没人再点它。拿不准的一律放 `warn`。

## 改完自己验一遍

```sh
node 硬检.mjs 测试样本/
```

四篇样本，各有分工：

| 样本 | 应该是什么结果 |
|---|---|
| `干净-该零报.md` | **零报**（防误报的底线，这篇一报就是规则写宽了） |
| `脏-该全报.md` | 大面积报（每类规则都故意犯一次） |
| `脏2-补漏规则.md` | 补测字段散落正文、表格缺分隔行、疑似口吻 |
| `出处档-真第一.md` | 没带口径的报「证」、带了口径的降「提」、主观评价照拦、正常表达零报 |

规则覆盖检查（确认没有从不触发的死规则）：

```sh
node --input-type=module -e "
const {checkText}=await import('./lib/执行器.js');
const {WORD_RULES,STRUCTURE_RULES}=await import('./lib/规则表.js');
const fs=await import('node:fs');
const fired=new Set();
for(const f of fs.readdirSync('测试样本')){
  const r=checkText(fs.readFileSync('测试样本/'+f,'utf8'));
  for(const i of r.issues) fired.add(i.ruleId);
  console.log(f.padEnd(24), r.verdict.padEnd(6), JSON.stringify(r.counts));
}
const all=[...WORD_RULES,...STRUCTURE_RULES];
const miss=all.filter(x=>!fired.has(x.id));
console.log('覆盖:',all.length-miss.length,'/',all.length, miss.length?'没触发: '+miss.map(x=>x.id).join(','):'全覆盖');
"
```

## 接工作台（还没做）

`lib/执行器.js` 的 `checkText(正文)` 是纯函数，不读文件、不联网。接右栏时：

1. 宿主加一条路由 `POST /api/workbench/check`，**由前端点名要查哪几篇**，
   只读点名的文件，不扫目录 —— 右栏显示的那几篇本来就已经按本任务过滤过
   （`updatedAt >= 任务发起时刻`），所以**界面上看到几篇就查这几篇**
2. 结果按「文件 mtime + rulesVersion」缓存：正文一改灯自动灭，规则一升级旧结论作废
3. 有「拦」或「证」→ 禁用「确认入库」，可逐条点「忽略」放行并记一笔
