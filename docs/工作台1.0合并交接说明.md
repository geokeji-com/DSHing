## 功能线独有的改动清单（合并时逐项落到 main 上）

### client.js（纯前端为主，冲突面小）
1. **薄弱问句整套 UI**（~1500 行）：`useWeakGaps`（含 `fresh=1` 语义）、`weakErrorText`、`gapText`、`weakVisible`/`weakSortRows`/`weakSelectionText`、词根/平台矩阵表（多选、选前10、拖扫、按客户分开存的勾选）、⤢ 放大、CSS（`.wb_tblGap` 等）、主题页签「薄弱问句/输入」。
2. **发送前确认卡**：`confirmOpen` state + Esc/遮罩关闭、`confirmTopicText`/`confirmHowText`、确认卡 JSX（装配台 return 末尾）+ CSS（`.wb_confirmMask/.wb_confirmCard/.wb_cRow...`）。
3. **预填语义**（composePrompt）：
   - 主题只列问句编号（不带差额/平台数据，无排序话术）
   - 覆盖要求：勾 N 条覆盖 N 条，同语义可合并，当次指令优先
   - 行为守则④：落草稿即停、自查≠审核、结论一律「待人工审核」
   - 知识库读法：`list_kb_files` + 逐个 `read_kb_file`，别用 `read_kb` 一把读
4. **R 区**：`confirmOne`/`confirmTargets` 失败显示真实原因（不再一切失败都报「重名」）；「已审完」→「已检查」。

### impl.js（⚠️ 与 main 的安全结构纠缠，不能直接搬）
- insights 客户端 + 5 分钟 TTL 缓存 + `weak-gaps`/weak 客户名单路由 —— **按 main 的 ACL/per-user 模式重写后再进**。
- `WEAK_CLIENT_MAP`（客户名→洞察 ID）：**民师已换 `2102224433627402240`**（2026-10-10，旧的 2058… 已失效）。
- confirm-draft 的「重名自动加时间戳」逻辑 —— **与 main 的 write_article(draft:false) 方案冲突，见下**。

### services/articles/server.mjs（已在 main，`services/`）
- `write_article` 带 `draft` 参数，**缺省 `draft:true` 落草稿区** —— 人审门禁的结构性实现。
- main 的 confirm-draft 已经走 `write_article(draft:false)`，两边**天然衔接**，impl 里不再需要 copy 版改名逻辑。
- 待对齐：重名时的行为（409 拒绝 vs 自动时间戳）落在哪层 —— 找同事（写 P2 的人）对。

## 建议合并顺序

1. 前端功能块移植（client.js，清单 1-4，纯新增为主，冲突小）→ `node --check` + 跑 `test/` 套件 → PR。
2. impl 的 weak-gaps 路由按 ACL 模式重写 → PR（需理解 main 的 grants 结构）。
3. 两个 PR 都进 main 后，**统一部署到服务器**（部署源 `server-ref` 换成 main 版），服务器同时获得安全修复 + 全部功能。
4. 部署后回归清单：确认卡、勾选按客户存、薄弱问句矩阵、R 区检查/入库、mobile+dark 不回归。
